阅读和恢复

阅读

克隆或下载仓库，使用浏览器打开 生成式软件工程/课程索引.html。10 篇现行笔记均内嵌图片，可离线阅读。GitHub 文件页只显示源码；下载后打开 HTML。也可下载 Release 的 course-reading-2026-10-27.zip，这是只含现行阅读成品的便携包。

取得源视频

gh release download snapshot-2026-10-27 --repo zhao-d-r/generative-software-engineering-2026 --pattern '*.mp4' --dir media
python3 tools/verify_archive.py --media-dir media

仓库和 Release 公开可读；gh 命令需要可用的 GitHub CLI 环境，也可直接从网页下载。archive/media-manifest.json 将 Release 的 BV 文件名映射到原始视频名、来源 URL 和 SHA-256。

恢复 BaoCut

  1. 先校验 python3 tools/verify_archive.py，把需要的 .bcut 目录复制到新的工作位置；不要直接编辑仓库中的档案。
  2. 下载对应原视频并按媒体清单核对哈希。
  3. 用兼容的 BaoCut 打开项目副本；原项目保留了旧机器的媒体绝对路径。若媒体离线，通过 BaoCut 的项目设置/重新关联媒体操作选择已下载文件，不手改 .bcut 内部 JSON。
  4. 检查转写、章节、Studio 与媒体能否正常工作。只有完成这些实际检查，才能声称跨机器原生恢复成功；本次未在第二台机器验证。

工作流快照见 tooling/baocut-course-notes/；BaoCut App、模型和登录/密钥配置不分发。历史脚本可能仍引用原工作目录，应先审阅路径和依赖。完整重算会产生新版本及新审查记录，不能把归档中的旧 PASS 当作当前机器的 PASS。

制作档案与证据边界

  • 生成式软件工程/ 保存现有课程目录、转写分块、notes/layout、讲义、全部候选帧、逐图审核、浏览器截图、修订与失败记录。
  • baocut/projects/ 保存 10 个原生 .bcut 目录：原始转写、ASR rows、Studio、历史对象、项目内 tasks/logs/cache 均保留。
  • legacy/ 保存可识别的早期复用草稿及提示词工程截图，不替代现行笔记。
  • media-manifest.json 对应同仓库 Release 中 10 个源视频，记录平台 BV ID、原始路径、长度与 SHA-256。
  • source-copy-manifest.json 记录源文件与复制指纹；transformations.json 单独记录归档转换；exclusions.json 列出未复制的 OS/Python 缓存和临时锁。

唯一内容范围转换是 生成式软件工程/sources/projects.json：从历史全机项目列表中去掉其他课程条目。历史 trace 仍保留原值，因此涉及该文件的旧快照不是归档副本的新验收结果。本次完整性以 files.json 和 publication-review.json 为准；不修改历史 passed/hash。

历史审核是原制作时的证据，包含真实手机、原生打印、音频逐秒听审等未测边界。复制文件并不构成新的全文/来源/真机验收。历史绝对路径、工具路径和状态照存，跨机器不自动有效。不要执行旧 ownership.json 或临时脚本来覆盖当前目录。

截至本次归档，在这 10 个 .bcut 项目和可识别的课程原件中未发现独立音视频 slices。存在的 chunks/ 是转写阅读分块；frames/、visual/ 是真实画面候选与审查资料；项目 cache/ 中已有 waveform 文件也予以保存。没有为上传重新转码或制造 slices。
